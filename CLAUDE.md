# CLAUDE.md

Dataset investigation workspace (not an application). We survey public datasets before training models for **plant disease/pest ("plague") detection and plant growth**, with emphasis on **berries (strawberry, blueberry, raspberry)**, plus **tomato, pepper and cucumber** (both studies) and **hydroponic growth** (growth only). Each study = one notebook (one section per dataset) + one findings markdown written as a team handoff.

## Normalized per-crop datasets

`normalization/normalized_<crop>.ipynb` (strawberry, blueberry, raspberry, tomato, bell_pepper, cucumber), all generated by `tools/build_normalized_nbs.py`, merge the surveyed sources into `normalized/<crop>/`. Layout:
- `images/`
- `labels/classification/{condition,maturity}.csv`
- `labels/{detection,segmentation}/{condition,maturity}/*.txt`: YOLO boxes / YOLO-seg polygons, normalized. Each axis folder has its own `classes.txt`, so condition and maturity train as separate models. Maturity = `flower`, `bud`, `fruit__<stage>`.
- `manifest.csv`, with license, a `group` leakage key and `label_space` per image. Split train/val/test by `group`, never by image. `label_space` lists the detection classes the image's source annotates (mask the other classes, do not treat them as background). `dhash` is written with a `0x` prefix (see traps).

Label rules (details in each notebook intro):
- **Image-level `condition` from boxes** only when every condition box in the image agrees.
- **Healthy** only comes from an explicit label, never from missing boxes.
- **Coarse source classes** stay coarse, e.g. `fruit__unripe`, `fruit__half_ripe`.
- **Detection files:** an empty file = verified negative, and only exists in `condition/`. No file = not annotated.
- **Classification labels are dropped** when near-duplicates disagree. A near-duplicate has the same 64-bit dHash, confirmed by a 256-bit dHash at most 10 bits apart.

Correctness first: labels that cannot be trusted or reconciled are dropped and counted in the notebook. Each run wipes and rebuilds its crop folder. Round-trip sample figures (labels read back from disk) go to `examples/normalized/`. Excluded on purpose:
- chili
- LeafNet2.0
- AgML strawberry/avocado
- Imtiaz tomato detection
- Raspberry images with broken point labels

Run the notebooks **one at a time**, never in parallel: six kernels at once ran out of RAM and killed one. Total runtime is ≈45 min (tomato and strawberry are the long ones). Run it in the background.

```bash
python tools/build_normalized_nbs.py && for c in strawberry blueberry raspberry tomato bell_pepper cucumber; do jupyter nbconvert --to notebook --execute normalization/normalized_$c.ipynb --inplace --ExecutePreprocessor.timeout=7200; done
```

Each notebook ends with `check()`, which reads every file back from disk and asserts the format. Because `finalize()` only runs at the end, a crashed run leaves `images/` with no labels: rerun that crop.

### Labeling tools (bell pepper)

- **`tools/prelabel_bell_pepper_seg.py`** fine-tunes yolo11n-seg on `normalized/bell_pepper/labels/segmentation/condition` (split by `group`). It then prelabels PlantDoc bell pepper images into `prelabel/bell_pepper/plantdoc_prelabels/`: labels, overlays and `review.csv` with flags.
  - Result: val mask mAP50 0.55.
  - Weakness: many confident false masks on soil/mulch, because the training lesions are tiny (median 0.09% of the image).
- **`tools/seg_labeler.py`** is a tkinter polygon labeler that reads YOLO-seg files. 5-value YOLO detection lines load as rectangles.
  - Edits are written to `--out` only; the input `--labels` folder is never modified. A file in `--out` = reviewed, an empty file = reviewed with no labels.
  - `--match 'plantdoc_*'` filters images. `--review review.csv` puts flagged images first.
  - `--export-boxes DIR` converts reviewed polygons to YOLO boxes. `--selftest` runs its checks.
  - The usage examples are in its docstring.
- `prelabel/` holds unverified labels. Never merge them into `normalized/` before review.

`archive/` holds the original `lol.ipynb`, its charts and `PLAGUE_DATASET_FINDINGS_v1.md` (which still documents the discarded datasets). Do not edit it.

## How notebooks are made

Notebooks are **generated**, not hand-edited: `tools/build_<study>_nb.py` writes the cells with `nbformat`. To change a notebook, edit its builder, then rebuild and execute from the repo root:

```bash
python tools/build_growth_nb.py && jupyter nbconvert --to notebook --execute growth.ipynb --inplace --ExecutePreprocessor.timeout=1800
python tools/build_plague_nb.py && jupyter nbconvert --to notebook --execute plague.ipynb --inplace --ExecutePreprocessor.timeout=3600
```

Runtime with a warm cache: growth ~1.5 min, plague ~15 min (header scan of LeafNet's 256k images). Run long ones in the background. Check that no cell has an `error` output after running.

Every number in a findings file must come from executed notebook output. After any change, re-run the notebook and spot-check the md against it. Before replacing a findings file wholesale, copy the old one to `archive/`.

## Conventions

- **One section per dataset:** source/paper + license → load → classes/stages chart → sizes → sample grid → gotchas (⚠️).
- **Sample grids** go through `show_samples(...)`, which also saves to `examples/<study>/<title slug>.png`. Draw boxes/polygons on samples and look at them to confirm labels land on the object. Several label bugs (wrong names, swapped W/H, fake boxes, mosaics, background confounds) were only found this way.
- **Charts** (from the dataviz skill; run its palette validator before adding colors): Growth uses a 5-step single-hue blue ordinal ramp for the common fruit-stage scale (8 steps failed validation) plus gray for overripe. Plague uses condition kinds: blue `#2a78d6` healthy, orange `#eb6834` disease, aqua `#1baf7a` pest, yellow `#eda100` deficiency, gray `#898781` plant part. Aqua and yellow are under 3:1 contrast, so every bar needs a direct value label. Berries are listed first and in bold. Title on the left, muted ink for text, light grid. Charts are saved at 150 dpi.
- **Common fruit-stage scale** (growth): flower/bud → green → white/pale → turning → ripe (+ overripe/rotten). Every dataset's classes are mapped onto it.
- Read only what you need: parquet row groups / image headers (`scan_parquet`, `image_sizes`), never `load_dataset` on huge sets (PlantDoc is 30 GB in memory). Iterate datasets row by row instead of pulling a whole image column into memory.
- Checks every dataset gets: license, splits, class balance, class names actually present, bbox convention (xywh px vs xyxy vs normalized), boxes outside the image, duplicates/leakage (Roboflow `.rf.<hash>` stems, augmentation suffixes, md5, perceptual hash across datasets), time-series fields, capture setting / confounds, web/watermarked images.

## Known dataset traps (details in the findings files)

- AgML parquet files can embed different class names than the card: use the card (`card_class_names`). Blueberry maturity ids: 0 = unripe, 3 = ripe.
- Strawberry/avocado (AgML): classes unnamed; portrait-photo boxes use swapped W/H.
- Raspberry (Roboflow): 14% of train labels are point labels turned into giant boxes (`broken_polygon`).
- Roboflow-origin sets (strawberry 5-stage, chili, mango) contain augmented copies: split by source-photo stem. Chili and mango stages are confounded with background/source.
- LeafNet2.0 ⊃ PlantVillage and PlantWild ⊃ PlantSeg (perceptual-hash checked): de-duplicate before combining.
- Strawberry_12: no class names shipped; mapping recovered from file-name prefixes (in `tools/build_plague_nb.py`). 57% of images are `_blur/_bright/_dark/_noise` copies, and some originals are mosaics or have cutout boxes.
- PlantDoc: class names missing (mapping in the builder and findings).
- Laboro tomato: 305 images are EXIF-rotated and their boxes are in the rotated frame: use `ImageOps.exif_transpose`.
- AgML `tomato_leaf_disease_detection` ships class names `'0'..'6'`; only id 2 = healthy is known.
- Mendeley/4TU data: list files via `https://data.mendeley.com/public-api/datasets/<id>/files?folder_id=root&version=<v>`, whole zip via `/public-api/zip/<id>/download/<v>`; 4TU via `https://data.4tu.nl/v2/articles/<id>/files`. `openpyxl` is not installed (HydroGrowNet sheets read with stdlib).
- LeafNet2.0 contains black pepper (*Piper nigrum*): not Capsicum. Its chili and cucumber classes match COLD augmented and AgML cucumber originals by count.
- **pandas 2.3 segfaults** (C CSV parser) on a hex string like `1e00…` that looks like a float with a huge exponent. Prefix hashes (`0x…`) or read with `dtype=str`.
- 64-bit dHash gives false near-duplicates on fixed-camera scenes (lab peppers, robot frames). Confirm a match with a larger hash before acting on it.
- CCMT has 12 tomato images that cannot be decoded. Strawberry_12 "originals" include 147 rotated copies with black corners (dropped).
- PlantSeg v3 has no healthy class. IP102 (AgML "CT_PestNet") is classification only, with mixed life stages and watermarked web images. CCMT has 831 byte-identical duplicates.
